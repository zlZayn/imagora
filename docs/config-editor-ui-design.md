## 0. 一句话设计原则

**这个弹窗是配置文件的可视化编辑器，不是配置管理器。**

| 原则 | 含义 |
|---|---|
| 只读信息不伪装成输入框 | 服务端已有值 → 只读行展示，不给输入框 |
| 写入 = 改文件 | 保存写的是磁盘文件，不是内存状态 |
| 危险操作独立 | 清空密钥不与普通保存同路 |
| 少即是多 | 只暴露真正会改的 4 项 |

## 1. 字段清单与写入目标

### 1.1 关键事实：`.env` 只管两样东西

`_load_env_file()`（[config.py](../core/config.py) 的 _load_env_file()）只把 `.env` 里的键灌进 `os.environ`，实际被消费的两类只有：

- `ACTIVE_PROFILE`（决定用哪个 profile）
- `API_KEY_<PROFILE>` / `API_KEY` / `AIWANWU_API_KEY`（密钥）

而 `base_url` / `api_paths` / `default_model` 走的是 `_get()`（[config.py](../core/config.py) 的 _get()）：

```python
def _get(key: str):
    return _profile.get(key, _DEFAULTS[key])  # 只读 config.json，无 .env 兜底
```

**结论：这三个字段只能写进 `config.json`，写进 `.env` 会被静默忽略。**

### 1.2 字段表

| # | 字段 | 写入文件 | 写入路径 | 频率 | 控件 | 只读显示 | 敏感 | 校验 |
|---|---|---|---|---|---|---|---|---|
| 1 | 接口地址 | `config.json` | `profiles[active].base_url` | 低 | 文本框 | 完整 URL + 来源 | 否 | blur |
| 2 | 接口路径 | `config.json` | `profiles[active].api_paths.generations` | 极低 | 文本框 | 路径 + 来源 | 否 | blur |
| 3 | 默认模型 | `config.json` | `profiles[active].default_model` | 中 | 下拉 | 模型 id + 来源 | 否 | 无需 |
| 4 | API Key | `.env` | `API_KEY_<PROFILE 大写>` | 极低 | write-only | `● 已设置` + 来源 | **是** | 非空 |

> ⚠ **待决**：`config.json` 是 **git 跟踪**的（`.env` 被 ignore）。UI 改它 = 每次产生一个 diff。
> 见 §8 待决问题 A。

### 1.3 第一版不暴露的字段

| 字段 | 为什么 |
|---|---|
| `ACTIVE_PROFILE` | 切 profile = 换一整套（地址+模型+尺寸+价），半套切换无意义 |
| `profiles.*.sizes` / `ratios` | 价目表，7×4 表格编辑 = 配置生成器，不是编辑器 |
| `quality_options` / `default_quality` | 几乎不变 |
| `default_output_dir` | 每次任务都记忆，用不上固定值 |

## 3. 密钥的 write-only 交互

### 3.1 只读行

```
API Key    ● 已设置                    .env API_KEY_WANWU
```

**永不显示值**，连掩码都不显示 —— `sk-****` 暗示"我看到了开头"，没有意义。

### 3.2 输入形态

```
API Key    [●●●●●●●●●●●●●●●●●●]  👁
           ● 已设置 · 写入后无法再查看
```

| 决策 | 选择 | 理由 |
|---|---|---|
| 用 `type=password`？ | **是** | 输入时遮蔽，防止屏幕共享/旁观时泄露。**不暗示能看回来**（无"显示"按钮、无复制按钮） |
| 失焦后清空？ | **否** | 误失焦（点别处、切窗口）就丢用户刚粘的 Key，比"被看见"更糟 |
| 保存后清空？ | **是** | 保存完成即清空并回到只读态。配合 §5「不自动关窗」，这是唯一能移除 DOM 里明文的时机 |
| 预填旧值？ | **否** | 有值 = 要改，空 = 不改。这是「留空不修改」的根本表达 |

**收敛后的论证**：这里不是"要不要遮蔽"的取舍，而是**遮蔽输入过程** vs **假装能回显** 两个独立选择。前者要（低成本无副作用），后者不要（会骗用户）。`type=password` 只解决前者，不附带任何"可查看"的暗示，所以它是对的。

### 3.3 「留空 = 不修改」的三层表达

| 层 | 手段 |
|---|---|
| 1 | placeholder = `留空则不修改` |
| 2 | 永不预填 → 空就是不改，无歧义 |
| 3 | 输入后行内提示 `将覆盖当前密钥` |

### 3.4 清空密钥 —— 独立出口

编辑区下方，`.btn-ghost.btn-sm` + `text-neutral-400`：

```
[ 清空此密钥 ]
```

二次确认（`ModalShell nested`）：

```
清空 API Key？
删掉后生成任务会失败，直到重新填入。
此操作只注释掉 .env 里那一行，可手动恢复。

                  [ 取消 ]  [ 确认清空 ]
```

三件事说清：**后果**（生图失败）、**可恢复**（注释非删除）、**影响面**（哪个 key）。

## 4. 保存按钮状态机

| 状态 | 保存按钮 | 表单 | 顶栏角标 |
|---|---|---|---|
| **无变化** | 灰 `disabled` | 无标记 | 不变 |
| **有变化** | 亮 `.btn-primary` | 改动行尾 `● 待写入` | 不变 |
| **保存中** | `写入中…` + `.btn-busy` | 全部 `disabled` | 不变 |
| **成功** | 文字变 `✓ 已保存`（**不关窗**） | 待写入消失 → 行尾 `● 待重启` | **黄标 `N 项待重启`** |
| **失败** | 回到「有变化」 | 顶部红条：服务端原话 | 不变 |
| **外部冲突** | 回到「有变化」 | 顶部琥珀条 + 刷新入口 | 不变 |

### 4.1 「有变化」的判定

```
dirty = ∃ 字段 formValue ≠ fileValue   （URL 先归一，避免尾斜杠造成假 dirty）
```

与文本编辑器 Ctrl+S 同构：没改动时按保存是灰的。

### 4.2 保存后不关窗

按钮位置短暂显示 `✓ 已保存`，**2 秒后回到无变化态**。理由与 Ctrl+S 一致 —— 保存不等于关闭编辑。

**期间**：表单进入只读（防保存后继续编辑造成"以为又改了"），Token 行清空，文件路径区可见写入结果。

**失败绝不关窗、绝不丢值。**

## 5. 并发与外部修改

### 5.1 一个机制覆盖两种场景

你说的第 1、2 点其实是**同一个机制**：

```
打开弹窗 → GET /api/config 记录 fileState.{configJson, env} 的 mtime
保存       → POST /api/config 带上 expectedMtime
服务端比对 → 不一致则 409，前端弹「文件已被外部修改」
```

- 场景 1（你用 VS Code 改了）：mtime 变了 → 409
- 场景 2（另一个窗口先保存了）：mtime 变了 → 409

不需要两套逻辑，一个 `expectedMtime` 就够。

### 5.2 冲突时的交互

```
⚠ 文件已被外部修改（.env · 12:04:31）
  你的修改尚未写入。继续保存会覆盖磁盘上的新内容。

              [ 放弃我的修改 ]  [ 查看差异 ]  [ 仍然覆盖 ]
```

**"仍然覆盖"要有，但放在最后** —— 默认路径是"放弃我的修改并重新读取"（安全），覆盖是用户明确知道后果后的选择。

**"查看差异"第一版不做** —— 需要引入 diff 库和 UI，成本远超收益。用户要对比可以自己去开编辑器。

### 5.3 为什么要 mtime 而不是内容哈希

mtime 一次 `stat()` 就有，零依赖；内容哈希要读全文。mtime 精度在 Windows NTFS 下是 100ns，足够。
（罕见误报：同一秒内的两次写。后果是多弹一次确认框，无数据损失 —— 可接受。）

## 6. 「待重启生效」

### 6.1 数据来源

`GET /api/config` 的 `fileState.fields[k].pending`：

```
pending = (文件里的值) ≠ (进程当前生效的值)
```

**服务端算**，前端不自行比对 —— 前端没有"生效值"的权威来源。

### 6.2 三处表达

| 位置 | 形态 | 作用 |
|---|---|---|
| 字段行尾 | `● 待重启`（`.chip--pending`） | 默认可见，精确到字段 |
| 顶栏角标 | `N 项待重启`（点击列出 key） | **唯一能跳出弹窗看到的** |
| 弹窗顶部 | 汇总条 | 刚保存完的即时反馈 |

### 6.3 不做 Safe / Restart 分类

本项目**全部字段都是 import 时求值的模块级常量**（`BASE_URL = _get("base_url")` 等，[config.py](../core/config.py)），**没有"可热加载"这一类**。

有人做过 Safe/Restart-required 的分类（思路是给每个 key 打标签，dashboard 显示哪类已同步、哪类待重启），但它的前提是**确实存在一部分可热加载的 key**。这里不存在，现在硬分两类就是骗自己。等将来真加了 `reload_config()` 再细分。

### 6.4 不提供「重启服务」按钮

第一版只提示。重启 = 进程死亡，正在跑的任务全丢。手动重启工作台成本可接受。

## 7. 校验时机

**结论：blur 校验格式，submit 做最终判定，不做实时。**

| 字段 | blur | submit |
|---|---|---|
| 接口地址 | 必须能解析出 host | — |
| 接口路径 | 必须以 `/` 开头 | — |
| 默认模型 | — | — |
| API Key | — | 非空时提示"将覆盖" |

**不实时**：打字过程中 `https` → `https:` → `https://` 每一步都"不完整"，全是噪声。blur 时输入已成型。

**Key 不做格式校验**：`sk-` / `ark-` 前缀各家中转站不统一，校验前缀等于给用户找麻烦。

不用现成 `text-amber-600` —— 那是**语义警告**（成本超限、参考图丢失）。待重启是**状态**，混用会让警告失去含义。

本弹窗**只用 3 档**，全走 Tailwind scale，不用 `text-[Npx]`：

| 用途 | 类 | 实际 |
|---|---|---|
| 弹窗标题 | `text-base font-semibold` | 16px |
| 字段名 / 只读值 | `text-sm` | 14px |
| 提示 / 来源 | `text-xs` + `.text-caption` | 12px |

**从最容易重写的弹窗开始收敛**，而不是全仓推 lint。

## 9. 文件路径展示

```
config.json · .env ⧉
```

**默认只显示文件名** —— 绝对路径（`D:\ProjectSomething\imagora\config.json`）在 560px 弹窗里必然溢出。

点击 ⧉ **复制绝对路径到剪贴板**，并 toast 提示 `已复制`。不用 `title` tooltip（原生 tooltip 无法控制层级，且我们刚在画布上踩过这个坑）。

底部这一行同时承担**写入结果展示**：保存成功后显示 `已写入 config.json`。

> 为什么不完全隐藏路径：这个 UI 的全部合法性建立在"我在改哪个文件"上。完全不显示 = 用户无从判断。

## 10. 有争议的点与取舍

| # | 争议 | 选择 | 理由 |
|---|---|---|---|
| 1 | 只读值要不要可编辑？ | 分成上下两区 | 一个是"事实"、一个是"意图"。同框切 `readOnly` 正是旧弹窗的困惑根因 |
| 2 | 编辑中的值实时同步到只读区？ | 不同步 | 只读区回答"现在实际在用什么"，保存后才合并 |
| 3 | 模型不在清单内怎么办？ | 保留为「当前：xxx（不在清单中）」选项 | 强制选清单内 = 剥夺"我用自定义模型"这个合法场景 |
| 4 | 保存后关窗？ | **不关窗**，按钮显示 `✓ 已保存` 2 秒 | 与 Ctrl+S 心智一致 |
| 5 | 保存后把表单锁只读？ | 是，2 秒 | 防"保存完又改、又以为保存了" |
| 6 | 冲突时默认动作？ | 默认**放弃我的修改**并重读 | 覆盖是危险操作，不该是默认路径 |
| 7 | 「查看差异」按钮？ | 第一版不做 | 要引 diff 库+UI，成本远超收益 |

## 11. 待决问题

### A. `config.json` 是 git 跟踪的 —— UI 改它会产生 diff

现状：`.env` 在 `.gitignore`，`config.json` **被 git 跟踪**（`git ls-files` 确认）。

| 选项 | 做法 | 代价 |
|---|---|---|
| **A1 直接写 config.json** | 写 `profiles[active].xxx` | 每次保存产生一个 diff。单人项目，实际无所谓 |
| **A2 给这三个字段加 .env 覆盖** | 改 `_get()` 支持读 `IMAGORA_BASE_URL` 等环境变量 | 新增能力（改配置解析逻辑），但 `.env` 被 ignore = 不产生 diff，且与现有 `.env` 语义一致 |
| **A3 第一版只写 .env 的 Key** | 三个字段仍手改 | 覆盖不了实际需求 |

**我倾向 A2** —— 它让「UI 写的所有东西都在 git 忽略的文件里」这条规则成立，且 `.env` 本来就是"本机私有覆盖"的定位（`ACTIVE_PROFILE` 已经这么用了）。
**代价是要动 `_get()`**，属于新增解析层，但逻辑很小。

**但 A2 是新增能力，不是纯前端改动** —— 需要你明确同意我才动 `config.py` 的解析优先级。

### B. `expectedMtime` 粒度

两个文件各自带 mtime（`config.json` 与 `.env`），还是整个配置用一个？
→ **建议各自带**：`.env` 和 `config.json` 是两个独立的冲突域，用户只改了其中一个时不该被另一个拦住。
