# 纯网页图片工具箱设计

## 目标

将现有四个可在浏览器本地运行的图片工具整合为一个可部署到 Vercel 的静态网站。网站不依赖服务器、不上传图片、不需要新增付费服务。

## 范围

第一期包含：批量加水印、图片压缩、批量白底、商品边框合成，以及一个工具首页。

生图工作台和药品查询不纳入第一期。两者分别需要保护生图 API 密钥和药品数据，并依赖服务端长期存储；后续如需多人共用图片库，再单独建设服务端版本。

## 使用方式

网站首页展示四个工具入口。进入任一工具后，顶部提供一致的工具导航。

每次导入或处理图片后，网站将当前图片保留在当前浏览器的内存中。用户可点击“发送到加水印”“发送到压缩”“发送到白底”“发送到商品边框”，跳转后目标工具自动使用该图片。

图片处理均在用户浏览器完成：不上传到服务器、不保存到云端。刷新页面、关闭标签页、换电脑或换浏览器后，当前图片将不再保留；用户仍可随时下载处理结果到本机。

## 架构

创建一个独立的前端项目，不改动现有 `imagora` 生图工作台。

项目使用 Vite、React 和 TypeScript：

- `App` 管理工具导航、当前图片和页面切换。
- 每个工具封装为独立组件，保留各自已有的浏览器处理算法。
- 共享的图片会话模块负责在工具之间传递 `File` 或 `Blob`。
- 页面路由使用浏览器地址栏的 hash，例如 `/#/watermark`，因此 Vercel 不需要服务器重写规则。
- 构建输出为静态文件，提交 GitHub 后由 Vercel 自动部署到 `toolboxonline.online`。

## 数据与隐私

图片内容仅停留在浏览器内存和用户主动下载的本地文件中。工具箱不包含账号、密码、API Key、数据库、远程图片库或统计追踪。

## 交互与界面

首页是简洁的工作台：显示四个工具、各自用途及最近使用的当前图片状态。各工具页顶部显示当前工具，右侧提供其他工具入口；当存在可传递图片时，跳转操作明确显示“已带入 1 张图片”。

针对批量工具，用户可继续上传多张图片；从其他工具传入的单张图片作为第一张任务图片，不覆盖后续手动上传。

## 错误处理

不支持的文件类型、损坏图片、超大图片或浏览器无法处理的格式均显示中文错误提示，并保留用户原来的页面状态。跨工具传递失败时，目标工具显示上传区域，不阻塞继续手动上传。

## 验收标准

1. 四个工具可在不联网的浏览器中完成图片处理（首次加载页面资源除外）。
2. 图片不会被提交到任何远程接口。
3. 任意工具中的当前图片可一键发送到另一个工具，目标工具自动读取该图片。
4. 处理后的图片可下载到本地。
5. 网站构建成功，并能作为纯静态网站部署到 Vercel。
6. 在桌面和手机宽度下，导航、上传和下载操作均可正常使用。

## 之后再做的内容

多人共用图片库、生图工作台在线版、药品查询在线版、账号密码和长期图片保存均属于下一期服务端项目，不包含在本期静态网站中。
