# Imagora 稳定性与前端整理设计

日期：2026-08-09

## 目标

在不替换现有 FastAPI、生图 API、输出目录和工作流 JSON 的前提下，把 Imagora 分两阶段推进到可稳定运行、可持续迭代的日常工作版本。

第一阶段解决已复现的 Windows 路径错误、画布任务并发和错误状态泄漏。第二阶段在稳定底座上整理画布前端的状态边界和视觉交互，不引入 ComfyUI/InvokeAI 的整套后端。

## 非目标

- 不更换上游生图服务或 API Key 配置方式。
- 不迁移已有输出图片、`.refs`、`.canvas` 或 `workflows` 目录。
- 不重写经典表单模式的业务流程。
- 不在本阶段增加用户系统、云存储、实时协作或真实 API 的集成测试。
- 自动保存不得覆盖用户手动命名并保存的工作流。

## 现状与根因

后端测试基线为 74 个通过、3 个失败。失败集中在 Windows 路径：跨盘路径传入 `os.path.commonpath` 会抛 `ValueError`，导致非法路径未按业务错误处理。

前端生产构建当前通过，但 `CanvasPage.tsx` 同时负责画布渲染、节点状态、连线约束、选择、高亮、上传、工作流存取、任务排队、并发生成、结果回流、自动布局、日志和弹窗。多个 `useRef` 与 React 状态共同维护异步状态，删除节点、重复点击和批量运行时容易出现状态残留。

## 阶段一：稳定性修复

### 路径安全

- 抽取可测试的路径判定 helper。
- 对不同盘符、非法路径、路径穿越和不存在文件统一返回拒绝结果，不向路由层泄漏 `ValueError`。
- `display_path` 在工作根外保持稳定的相对展示格式，不泄漏原始绝对路径。
- `delete_ref` 对非法路径保持幂等成功语义，避免清理操作阻断 UI。

### 画布任务调度

抽取纯 TypeScript 调度器，职责仅包括：

- 单节点运行锁，避免同一节点重复生成。
- 批量运行队列和并发上限。
- 节点删除后的取消/忽略保护。
- 成功、失败、重试时的状态清理。
- 统一的任务结果回调，不直接修改 React Flow 节点。

React 组件只订阅调度器状态并提交事件，不能同时维护另一套运行集合。

### 工作流兼容

- 保持当前 version 1 JSON 结构。
- 加载时校验节点类型、边方向和必要字段。
- 缺失图片继续进入 `missing` 集合并显示可识别状态。
- 重复导入和结果回流按 registry id 去重。
- 非法或损坏工作流返回可展示错误，不让页面进入空白状态。

### 自动保存与恢复

- 画布变更后防抖写入独立的恢复快照，不调用手动工作流的覆盖保存路径。
- 恢复快照使用固定的系统保留名称或独立恢复目录，并保留最近若干份轮转备份。
- 页面刷新或异常退出后提示恢复最近快照，用户可以选择恢复或忽略。
- 手动保存的命名工作流始终由用户显式保存、覆盖或删除，自动保存无权修改。

### 自动整理

- 修复现有“自动整理”按钮，稳定按参考图/图片组 → 提示词 → 结果图的层级排列。
- 多个提示词组之间保持固定间距，孤立节点单独成列。
- 整理后等待节点尺寸更新完成，再执行 `fitView`，避免布局位置正确但视口未居中。
- 空画布、单节点、缺失图片节点和重复共享参考图都不得使整理操作报错。

### 生成错误边界

- 后端对空结果、超时、非 2xx、响应格式错误和文件写入失败统一格式化。
- 前端无论成功或失败都清理计时器、busy 状态和运行锁。
- 错误日志包含任务节点、参考图数量和可读原因，但不包含 API Key。
- 连续点击不会重复提交；超时任务可以结束并重试，不能永久停留在运行状态。

## 阶段二：前端整理

### 组件边界

将现有画布拆成以下边界：

- `CanvasShell`：布局、工具栏和弹窗挂载。
- `CanvasViewport`：React Flow、节点/边事件和视图操作。
- `useCanvasController`：节点、边、选择、高亮和派生数据的唯一来源。
- `generationQueue`：队列、并发、重试和状态订阅。
- `workflowPersistence`：保存、加载、版本校验和错误转换。
- `CanvasNodes`：纯展示组件，只通过回调派发用户操作。

经典表单继续由 `App` 管理，但共享配置加载、输出目录记忆、计时和错误展示的 API helper。

### 交互与视觉

采用轻量专业的创作生产工作台风格：

- 工具栏按创建、运行、工作流、视图四个区域固定排列。
- 运行状态使用稳定的 queued/running/done/failed 视觉层级，避免按钮文字导致布局跳动。
- 结果画廊使用固定缩略图比例、懒加载和键盘可访问的预览/下载操作。
- 提供统一任务中心，显示排队、运行、成功和失败任务，并支持取消、失败重试和只重跑失败任务。
- 提供生成历史与图库搜索/时间筛选，可定位文件、重新使用图片或导入画布。
- 支持画布撤销/重做，覆盖节点移动、连线、删除和自动整理等可逆操作。
- 保持当前浅色、低装饰的产品基调，强化状态色和结果信息，不增加营销式大卡片或装饰背景。
- 桌面宽度和窄窗口都不得发生文字溢出、节点覆盖或工具栏换行错位。

### 默认质量

- 经典表单初始化质量统一为 `high`。
- 新建提示词节点默认质量统一为 `high`。
- 加载已有工作流时保留存档中的质量；旧存档缺少质量字段时回退为 `high`。

### 启动与运行检查

- 启动时检查 API Key、端口占用、前端构建产物和输出目录可写性。
- 检查失败时给出明确原因和处理办法，不静默退出或打开空白页面。

## 数据流与兼容性

浏览器继续通过 `/api/*` 调用 FastAPI。参考图仍先落盘到 `.refs`，画布图片仍登记在 `.canvas/registry.json`，生成结果仍写入用户选择的输出目录。新模块只改变前端内部调用方式，不改变现有 API 字段和工作流文件。

## 测试策略

### Python

- 新增跨盘路径、路径穿越、非法删除和输出路径边界测试。
- 保留现有纯函数测试，生成真实网络仍不进入测试。

### TypeScript

- 调度器测试：单节点去重、批量并发、失败清理、删除后忽略结果、重试。
- 工作流测试：version 1 往返、非法节点/边、缺失图片、重复结果。
- 自动保存测试：恢复快照轮转、刷新恢复、手动存档不被覆盖。
- 自动整理测试：多组节点、孤立节点、共享参考图、空画布和视口居中触发。
- 默认值测试：经典表单、新建节点和旧工作流缺省质量均为 `high`。
- 前端构建必须通过 `tsc --noEmit` 和 `vite build`。

### 浏览器验收

使用本地开发服务验证：经典/画布切换、上传参考图、单节点运行、全部运行、删除运行中节点、保存/加载工作流、自动保存恢复、自动整理、撤销/重做、任务重试、失败提示和图库预览。至少覆盖桌面和窄窗口两个尺寸。

## 验收标准

1. `uv run pytest -q` 全部通过。
2. `npm run build` 通过且无 TypeScript 错误。
3. 跨盘非法路径不再抛异常，所有路径测试通过。
4. 同一画布节点重复点击最多产生一个任务。
5. 批量运行达到并发上限，任务完成或失败后状态集合完全清理。
6. 已有 version 1 工作流可以加载、保存和再次运行。
7. 画布切换、窄窗口和错误状态不出现空白、重叠或永久 busy。
8. 自动保存只写恢复快照，手动命名存档内容和修改时间不被改变。
9. 自动整理在空画布、单节点、多任务组和共享参考图场景下都能完成并正确居中。
10. 经典表单、新建提示词节点和缺省旧工作流的默认质量均为 `high`。
11. 刷新后可恢复画布，失败任务可重试，生成历史可再次导入画布。
