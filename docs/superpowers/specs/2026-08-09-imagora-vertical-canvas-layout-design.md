# Imagora 上中下画布布局设计

## 目标

把无限画布从“左侧参考图、中间提示词、右侧结果图”改成纵向数据流，减少左右两侧大面积空白，并让自动整理、自动连线和手动拖线使用同一套空间规则。

## 布局结构

自动整理采用全局三层横向带：

1. 上层放参考图片；图片已加入图片组时，图片组放在图片下方。
2. 中层放提示词卡片；所有提示词保持同一横排，并按整理前的视觉顺序从左到右排列。
3. 下层放生成结果；结果图片排列在其来源提示词下方。

共享图片组只渲染一次。图片组位于它所连接提示词范围的水平中心，上方向下连接多张提示词，不复制节点或数据。

节点间距根据实际测量宽高计算；节点尚未测量时才使用类型默认尺寸。不同节点的边界至少保留固定间距，不能发生水平或垂直重叠。整理完成后继续执行 `fitView`。

## 端点方向

所有节点统一使用上方输入、下方输出：

- 图片节点：顶部接收提示词生成结果，底部作为参考图输出。
- 图片组：顶部接收图片，底部输出到提示词。
- 提示词节点：顶部接收图片或图片组，底部输出生成结果。

连线类型约束保持不变：图片可以连接图片组或提示词，图片组可以连接提示词，提示词可以连接结果图片。

## 自动连线

自动连线改用纵向位置判断：

- 图片位于提示词上方时，连接为图片到提示词。
- 图片位于提示词下方时，连接为提示词到结果图片。
- 图片优先连接位于其下方且距离更近的图片组。
- 新增提示词没有参考来源时，优先连接已有图片的图片组。
- 已有连线不删除、不重复；操作继续支持撤销。

## 特殊情况

- 没有提示词但存在图片组时，图片仍可自动连接到下方最近的图片组。
- 没有图片组时，参考图片可直接连接提示词。
- 孤立节点放在上层末尾的待整理区域，不挤入提示词或结果层。
- 一个图片组连接多个提示词时，提示词仍保持同一水平线。
- 一个提示词有多个结果时，结果在该提示词下方水平展开。

## 验证

- 单元测试覆盖纵向顺序、共享图片组、提示词横向对齐、上下方向自动连线和真实尺寸防重叠。
- 正式构建必须通过 TypeScript 检查。
- 使用当前恢复画布实测：自动整理后无节点重叠；手动端点位于节点上下边；新增提示词可自动获得图片组入线。
- 在桌面和窄窗口检查工具栏、节点内容和连线端点不被裁切。
