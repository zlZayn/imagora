# 备忘：CLI `--n` 会按多张计费但只保存一张（2026-09-29）

状态：生效

## 事实

- [main.py](../../main.py) 第 203 / 215 行把 `--n` 透传给 `generate_image`，进接口 payload 的 `n`。
- [core/api.py](../../core/api.py) 第 138 行只取 `response.json()["data"][0]`，只落盘一张。
- Web 端 [server.py](../../server.py) 的 `_run_task` 不传 `n`，走默认 `n=1`；线上不受影响。
- 结论：`--n 3` 触发接口出 3 张、按 3 张计费，实际只保存 1 张，另外 2 张被丢弃。

## 处置

- 本轮 UI 重构不修，仅记录。
- 后续三种走法待定，改前须确认（涉及接口层行为与计费口径）：
  - 真保存多张：`api.py` 遍历 `data[*]` 落盘，输出文件名加序号。
  - 移除 `--n`：既然保存不了多张，就不该暴露这个参数。
  - 保留但标注：命令行帮助里写明「仅保存第一张」。

## 影响

- 命令行用户若用 `--n`，存在实际扣费与产出不符的浪费。
- 网页端一次生成仍是一张图；多张只来自「画布上有几张提示词卡片」（`全部运行` / `运行所选`）。
- 若将来网页要支持一次出多张，除 `api.py` 外还需 `core/tasks.py` 传递张数、前端加张数选择，费用按张数计。
